Minor: app/controllers/custom_sql_search_controller.rb:33
When a field has a db_config, SqlTemplate.render is forced to dialect: :sqlserver regardless of the actual adapter configured in db_config. If administrators point db_config at a non-SQL Server database (e.g., MySQL or PostgreSQL), placeholder handling will use the wrong quoting/escaping rules, potentially breaking valid statements or mis-parsing comments/identifiers.
Failure scenario: An admin configures db_config to use a remote MySQL instance and writes a query relying on MySQL backticks or “--” comments without trailing space. The renderer runs with dialect :sqlserver, so backticks are treated as plain characters (not identifier quotes) and “--” comments are always treated as comments, changing parsing and producing SQL errors or wrong results.

  sql = CustomFieldSql::SqlTemplate.render(@custom_field.sql, params.as_json, trusted: trusted, dialect: mapped_dialect)
Alternatively, when with_another_database yields a connection, pass connection: other_connection to let SqlTemplate detect the dialect itself.

Resolution: no effect. with_another_database runs a statement only when the db_config adapter is sqlserver; for any other adapter it returns [] without running anything (unchanged upstream behaviour), so the :sqlserver dialect is exactly the one of every statement that runs. Not changed.
